Lab · Use case

One ticket in, one JSON object out

Input: a raw ticket

Hi, I was charged $49 twice for my
Pro plan this month. Can you fix
this ASAP?

Output: exactly this shape

{"category": "Billing",
 "priority": "High",
 "suggested_reply": "Hi, I’m sorry about
  the duplicate charge…"}

category

Routes the ticket to the right team’s queue.

priority

Starts the right response-time clock.

suggested_reply

Pre-fills the agent’s reply box. A person still approves it.

Make it concrete: one ticket in, one object out. Each field has a consumer in the ticketing system. The model does the grunt work; a human still approves the reply.
