Every knob, and why it’s set that way

SettingValueWhy
LoRA rank r16Enough capacity for one narrow task
lora_alpha32Strength = alpha / r = 2, the common rule
target_modulesattention + MLPBeats attention-only; the modern default
learning_rate2e-4LoRA’s sweet spot is 1e-4 to 3e-4
epochs3Small data: a few passes; watch eval loss
batch × accumulation2 × 8 = 16Big effective batch, small memory footprint
max_seq_length1024Well above the longest example: nothing truncated
precision, optimizerfp16, paged 8-bit AdamWT4 has no fast bf16; tiny optimizer memory

Out of memory? Raise accumulation, not batch size. Accumulation costs almost no memory.

Slow down here. The effective batch is per-device batch times accumulation times number of GPUs. If students hit OOM: first lower max_seq_length, then batch 1 with accumulation 16. On Ampere or newer, switch fp16 to bf16.
